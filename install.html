Gaming CMS – Plesk Installation (ohne install.sh)

Diese Anleitung ist fuer Webhoster gedacht, bei denen kein install.sh ausgefuehrt werden kann.

Voraussetzungen

  • PHP 8.2+ (mit Extensions: bcmath, curl, gd, intl, mbstring, pdo_mysql, xml, zip)
  • Composer 2.x (falls serverseitig nicht moeglich: lokal installieren)
  • MySQL 8+ oder MariaDB 10.11+
  • SSH oder Plesk Terminal empfohlen

Schritt 1 – Dateien hochladen

  1. Projektzip hochladen und entpacken.
  2. Stelle sicher, dass artisan, composer.json und public/ vorhanden sind.

Schritt 2 – Document Root setzen

  1. In Plesk: Websites & Domains → Hosting Settings
  2. Document Root auf public setzen.

Schritt 3 – .env anlegen

  1. Falls vorhanden: .env.example in .env kopieren.
  2. Folgende Werte in .env setzen:
APP_ENV=production
APP_DEBUG=false
APP_URL=https://deine-domain.de

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_DATABASE=gaming_cms
DB_USERNAME=dein_user
DB_PASSWORD=dein_passwort

Schritt 4 – Composer Dependencies

Wenn Composer auf dem Server verfuegbar ist:

composer install --no-dev --optimize-autoloader

Falls nicht moeglich, lokal ausfuehren und vendor/ mit hochladen.

Schritt 5 – APP_KEY generieren

php artisan key:generate --force

Schritt 6 – Migrationen ausfuehren

php artisan migrate --force

Optional Demo-Daten:

php artisan db:seed --class=DemoDataSeeder --force

Schritt 7 – Storage Link & Rechte

php artisan storage:link

Rechte setzen (falls moeglich):

chown -R www-data:www-data storage bootstrap/cache
chmod -R 775 storage bootstrap/cache

Schritt 8 – Caches optimieren

php artisan config:cache
php artisan route:cache
php artisan view:cache
php artisan filament:optimize

Schritt 9 – Assets bauen

Wenn Node vorhanden ist:

npm install
npm run build

Falls nicht moeglich: lokal bauen und public/build/ hochladen.

Schritt 10 – Test

  • Frontend: https://deine-domain.de/
  • Admin: https://deine-domain.de/admin
  • Demo-Login: admin@gaming-cms.local / password (nur wenn Seeder ausgefuehrt)
Hinweis: Wenn kein SSH/Plesk Terminal verfuegbar ist, muessen Composer, Migrationen und Assets lokal ausgefuehrt werden.

Troubleshooting (kurz)

  • 500 Fehler: Document Root auf public, Rechte fuer storage/bootstrap/cache pruefen.
  • DB Fehler: .env Werte pruefen, Datenbank existiert.
  • Assets fehlen: public/build/ fehlt oder nicht hochgeladen.
